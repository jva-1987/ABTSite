② Default

Task

Description

Certificate issuer

Organization name: Specify the name of the organization who will issue the certificate.

Organization department: Specify the name of the organizational department who will issue the certificate.

Location: Specify the location of the organization.

State: Specify the state of the organization.

Country: Specify the country code of the organization according to the ISO 3166-1 standard.
Note: Only characters 0-2 [A-Z] or numbers from 0 - 3 digits [0-9] are allowed. For example, Switzerland codes:

  • CH
  • 756

Not allowed, for example:

  • CHE (more than 2 characters)
  • CH1 (mixed characters and numbers)

Email address: Specify the email address of the organization.

Web server certificates

Certificate type: None, internal or external certificate.

External key type: Select one of the key lengths for the TLS certificate:

  • RSA 2048, 3072 (default), 4096
  • ECDSA 256, 384, 521

The selected length of the key depends on the existing IT infrastructure or the customer's security requirements. Clarify with the customer which key length is to be used.

If a setting is changed in ABT Site at later time, all CSRs certificates must be recreated.

A corresponding value must be entered, for example, in the RADIUS server. For more information, see chapter Editing the properties of the new template in the Document A6V16172313.

Certificate validity: Specifies for how long the certificate is going to be valid (in months).

  • Default is 60 months.

Expiration warning period: Set the time between expiry and the controller producing a notification to the user (in days).

  • Default is 90 days.

IEEE 802.1X certificates

Certificate type: None, internal or external certificate.

External key type: Select one of the key lengths for the TLS certificate:

  • RSA 2048, 3072 (default), 4096
  • ECDSA 256, 384, 521

The selected length of the key depends on the existing IT infrastructure or the customer's security requirements. Clarify with the customer which key length is to be used.

If a setting is changed in ABT Site at later time, all CSRs certificates must be recreated. See also:
Defining the IEEE 802.1X project properties for the root certificate

A corresponding value must be entered, for example, in the RADIUS server. For more information, see chapter Editing the properties of the new template in the document A6V16172313.

Certificate validity: Specifies for how long the certificate is going to be valid (in months).

  • Default is 60 months.

Expiration warning period: Set the time between expiry and the controller producing a notification to the user (in days).

  • Default is 90 days.

Identity: Describes the identity of the device, this depends on the requirements of the used RADIUS server or authentication service, for example, with Windows RADIUS (Network Policy Server) and Windows Active Directory, a user name like an email is required. The identity can be composed by a prefix, device identity and postfix:
for example, prefix, [selected option of device identity], postfix.

  • Prefix: Typically starting with a letter to compose a proper user name (in case of Windows Active Directory).
    Prefix makes it possible to create a user in the Windows environment that complies with Windows naming conventions for users. The prefix added to the device ID must include a letter (not just numbers). The name must not contain any special characters, such as “:”, “’” etc.).
  • Device identity: Typically describes the device with serial number, hostname or MAC address, but can be any arbitrary string.
    This also depends on the requirements of the authentication server being used. Clarify with the customer which information is to be used for the device identity (serial number, MAC address or hostname). The selected option must be aligned with the RADIUS server.
  • Postfix: Postfix makes it possible to create a user in the Windows environment that complies with Windows naming conventions for users. The value added in the postfix must begin with @, for example, @RadiusAD.net.
  • Subject alternative name: The subject alternative name (SAN) in an IEEE 802.1X certificate is used to specify the identity of the device that the certificate is issued to. The subject alternative name includes information, such as:
    • Identity only
    • Identity and IP/FQDN

  • Subject common name: The subject common name in an IEEE 802.1X certificate typically represents the name of the device that the certificate is issued to. The subject common name is a required field in the certificate and is used to identify the entity that the certificate is associated with. The subject common name includes information, such as:
    • MAC address only
    • Identity only
    • Identity and MAC address

Description

Actions

Export CSR for ABT signing certificate

Creates a root certificate for an external intermediate signing request. This file must be sent to a trustworthy authority, a certification authority that issues digital certificates.

Import signed ABT signing certificate

Imports the external intermediate signed root certificate from an external trusted certificate authority.

Generate new internal signing certificate

You can regenerate the internal root certificate. The device certificates for the regenerated root certificate need to be regenerated also. Therefore, a download must be carried out.

Only enabled with Administrator rights.
Regenerate BACnet/SC internal root certificate (BACnet/SC)

Export CSR for ABT operational certificate

Exports the signing request for the operational certificate. This removes the existing operational certificate keys from the project data and invalidates previous signing request. Note: This operation cannot be undone and the ABT Site is no longer a trusted device as long the new signing request is imported.

Import signed ABT operational certificate

Imports the external signed root certificate from an external trusted certificate authority.

Delete temporary root

Deletes the temporary root certificate. If all devices are updated with the new Main signed certificate, the Temporary signing certificate can be deleted. When deleted, a new ABT operational certificate is created at the same time. If an external certification authority has previously been used, this process must be repeated.
