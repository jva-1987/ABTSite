Multistate scheduler (MSchedule)

The object type scheduler multistate includes the BACnet properties for a multistate scheduler.

Naming

There is a dependency between 'Name', 'Description' and 'Naming extension'. Any changes to one impacts the other two properties.

The dependency can be eliminated by entering a project-specific text.

Example 1:
The preconfigured 'Description' "Room operating mode scheduler" sets the 'Name' to "ROpModSched" if selected. If "A" is selected as a supplement to the 'Naming extension', the description is supplemented by "(ventilation and air conditioning)" to "Room operating mode scheduler (ventilation and air conditioning)" and the 'Name' becomes "ROpModSched(A)". The name also forms the last element of the object name.

Example 2:
The preconfigured 'Description' "Domestic hot water scheduler" sets the 'Name' to "DhwSched" if selected. Selecting "01" (project-specific text) in addition to 'Naming extension', results in the 'Name' "DhwSched(01)". The name also forms the last element of the object name.

Name ✳

 

 

'Name' is a name specific to the instance. It is used to set up a hierarchical object name.

Property ID: 4438

Description

 

 

'Description' describes a BACnet object. The 'Description' is a translatable string that is saved internally as a text reference or directly as a string.

Property ID: 28

Name extension ✳

 

 

'Name extension' is an optional extension of the name extension path. It can be used to uniquely identify an object when needed.

Property ID: 4437

Designations from the text catalog can also be used for the 'Name extension'.

Object name

 

 

'Object name' uniquely designates a BACnet object within an automation station.

Property ID: 77

Object naming rule

 

 

'Object naming rule' defines the rule for setting object names during engineering. The value range is either 'hierarchical' or 'customized'. Under 'hierarchical', the object name is formed based on the hierarchy. The object name is set directly under 'Customized'. The BACnet hierarchy structure is irrelevant.
'Object naming rule' is an internal property. It is not accessible via the standard right/write procedure.

Property ID: 4436

Alarming

Alarming is implemented under the principle of intrinsic reporting within a BACnet object.

Select the Properties tab to add the extension, select 'Yes' in the Enable event field. The BACnet properties required for the setting are displayed in ABT Site and the Programming editor under the Properties tab.

Enable event

 

 

'Enable event' enables the alarm function. The BACnet properties required to set the function are displayed.

For setting 'Yes', the settings 'Extension with event configuration' is set to 'Intrinsic event registration'.

Property ID: 35

12: Low priority notification

14: Lowest priority notification (acknowledge)
15: Lowest priority notification
16: None priority notification
17: Buffer ready notification
18: Device alert notification

Property ID: 17

Enable event detection

 

 

'Enable event detection' enables event detection. The "Event state" is always "Normal" with setting 'No'.

Property ID: 353

Suppress event notification

 

 

'Suppress event notification' determines whether event notifications are suppressed.
No: No suppression. The events are reported.
Yes: Suppression of event notifications. All 3 bits for "enable event" are set to 'False'. When activated, a last event is sent with notification class 18: Device alert notification so that that recipient is aware of the suppression and are displayed accordingly.

Property ID: 4972

Configure event enable

 

 

'Configure event enable' property in BACnet is used to specify which event transitions are monitored and reported for a particular object.

Property ID:

Notification type

 

 

"Notification type" conveys whether the notifications generated by the object should be of type "Event" or "Alarm".

Configurable event message texts✳

 

 

'Configurable event message texts' contains three sets of character strings that are used by the 'Event message texts' property for notifications of "To-Offnormal", "To-Fault", and "To-Normal" events generated by this object. The character strings can optionally contain proprietary text substitution codes to incorporate dynamic information such as date and time or other information.

Property ID: 352

Other

Number of states

 

 

'Number of states' defines the number of states that can report 'Present value'.

Property ID: 74

State text

 

 

'State text' specifies the enumeration of the multistate value. Preconfigured enumerations can be selected or set to a project-specific enumeration.

Property ID: 110

Schedule default value

 

 

'Schedule default value' sets the default value used for 'Present value' if no other if not other scheduler value is active.
The schedule default value is between 1 and the number of states.

Property ID: 174

Priority for writing

 

 

'Priority for writing' sets the priority to command objects entered in the object list.
Priority range: 1...16

Property ID: 88

The object list can only be modified online with a BACnet browser in the current tool version.

Suppress fault monitoring

 

 

'Suppress fault monitoring' determines whether the fault supervision (fault events) is suppressed ('Yes'/'No'). The setting 'Yes' suppresses the evaluation of 'Reliability' and the value for 'Reliability' remains on "No fault".

Property ID: 357

Out of service

 

 

"Out of service" allows decoupling the object from being modified by a control program, system program or peripheral device.

  • If "Out of service" is TRUE, the properties "Present value" and "Reliability" will no longer be updated by the respective control program, system program or peripheral device.
  • If "Out of service" is TRUE, the properties "Present value" and "Reliability" can be modified for simulating and testing purposes.
  • If "Out of service" will be changed from FALSE to TRUE, the properties "Present value" and "Reliability" keep their values. Nevertheless, they can be individually modified afterwards.
  • If "Out of service" will be changed from TRUE to FALSE, the properties "Present value" and "Reliability" keep their values. They will be modified by the next update of the producer.

Property ID: 81

Object access level

 

 

'Object access level' defines the instance-specific object access level. 'Object access level' is used for generic filtering and processing of an object by a client application.

  • 'Object access level' is a configuration property that can only be set up offline (ABT, application configuration).
  • 'Object access level' is evaluated by the client applications.

Property ID: 4941

Object usage ✳

 

 

"Object usage" indicates whether the object is used or unused. The "Object usage" property can hide or display respective objects and their functionality in a client. For example, room functionality can be marked for flexible room arrangements as used/unused. An object that is marked as unused behaves as if the object does not exist.

Property ID: 4930

Object identifier

 

 

'Object identifier' is an invariant designator that uniquely identifies the object within an automation station.

Property ID: 75

Naming parent

 

 

'Naming parent' refers to the superposed BACnet object as per the (application) hierarchy.

  • The superposed object can refer to one BACnet object on the same device. A reference to a remote device is not possible.
  • The superposed BACnet object can refer to a BACnet object that is part of the common system hierarchy.

Property ID: 4398
